# Помощник на телефоне и компьютере

## Реализовано в этой версии

- Общий пакет `@workspace/poker-engine`: проверка карт, оценка комбинаций,
  вероятность единоличной победы, раздела и ожидаемая доля общего банка.
- Учитываются открытые руки активных соперников и известные карты сбросивших.
  Невозможные карты и диапазоны отклоняются; они не заменяются случайными руками.
- Полный перебор на ривере против одного соперника и на постфлопе при всех
  открытых руках. В остальных случаях используется Монте-Карло.
- Новая вкладка «Вероятность» работает в браузере телефона и компьютера.
  Изменения ввода запускают расчёт в Web Worker; устаревший расчёт отменяется.
  Снимок стола можно загрузить как ориентир для ручного ввода.
- Серверные советы и старый анализатор используют общий пакет. Вероятность
  единоличной победы и equity разделены; для EV используется equity.

Это ещё не универсальный автоматический помощник. Новая панель требует ручного
подтверждения карт и активных игроков, она не отправляет свои результаты в эфир.
Существующие «Экран» и «Эфир» остаются отдельным серверным сценарием.

## Захват экрана

Компьютер: существующий браузерный захват окна через `getDisplayMedia`, HTTPS
(или localhost при разработке), затем распознавание и API. Другие вкладки требуют
доступного API на том же origin `/api`, включая WebSocket `/api/ws`. Vite сейчас
не содержит прокси API; для полного приложения нужен reverse proxy или его
последующая настройка. Новая локальная панель API не требует.

Android: нужен нативный клиент с MediaProjection, системным подтверждением
захвата на каждую сессию и foreground service. Клиент должен отслеживать отзыв
разрешения, изменение размера/поворот и завершать захват при остановке сессии.
Такой клиент и его APK пока отсутствуют. Просмотр сайта на Android не даёт ему
автоматически возможность читать Telegram поверх другого приложения.

Источники платформенных требований:
- https://developer.android.com/media/grow/media-projection
- https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia

## Проверка распознавания на примере пользователя

2026-10-04, скриншот TON Poker 4MAX, Android, портрет. Ручная разметка:
свои карты снизу `7c 9h`; борд `9c 4c 2d 3d Kd`; открытая рука слева `4s 4d`.
Правый игрок виден, но его статус участия по одному кадру не установлен.

При запуске на полном исходном снимке через onnxruntime-web:
- `best.onnx`: свои карты верны; борд ошибочно `9c 9d`; остальные карты пропущены.
- `playing_cards.onnx`: `detectCards` вернул `null`.

Это диагностические результаты одного кадра, не оценка точности на всём наборе
TON Poker. Они доказывают, что автоматическую поддержку этого интерфейса пока
заявлять нельзя. Исходное пользовательское изображение в репозиторий не включено.

Для продолжения разработки запись от пользователя не обязательна; оплачивать игру
или пополнять баланс ради неё не нужно. В панели «Вероятность» есть «Демо без
депозита» — восемь явно синтетических наблюдений: префлоп, неполный борд во время
анимации, флоп, фолд, тёрн, ривер, вскрытие, завершение. Работают пауза, переходы
по кадрам и остановка при ручном редактировании. Автовоспроизведение ждёт окончания
расчёта перед отсчётом следующего кадра. Это проверка математики и интерфейса;
состояние берётся из сценария, а не из распознавания изображения.

Дополнительный опыт с тем же снимком: вручную обрезанные области борда, героя
и соперника также не дали корректного полного распознавания основной моделью.
Увеличение отдельных областей пока не решает проблему.

Для доказательства качества распознавания позже потребуются независимые реальные
изображения или разрешённые записи, не использованные при настройке. Можно
продолжать с имеющимся кадром и синтетическими сценариями; они не заменяют такую
проверку и не доказывают поддержку всех интерфейсов.

## Проверки и запуск

```sh
pnpm install --frozen-lockfile
pnpm run typecheck
pnpm --filter @workspace/scripts exec tsx --test ../lib/poker-engine/tests/equity.test.ts
pnpm --filter @workspace/scripts exec tsx --test ../artifacts/poker-advisor/tests/demo-hand.test.ts
pnpm --filter @workspace/scripts exec tsx ../artifacts/api-server/integration_test.ts
PORT=20319 BASE_PATH=/ pnpm run build
PORT=20319 BASE_PATH=/ pnpm --filter @workspace/poker-advisor run dev
```

Новая панель работает без API, Python, Telegram и БД. Существующий серверный
CFR-сценарий отдельно требует подготовленного Python-окружения.

## Оставшиеся части целевой системы

1. Надёжное распознавание и временное отслеживание стола на реальных записях.
2. Нативный Android-захват и вывод подсказки при открытом Telegram.
3. Разделение серверного состояния и эфира по сессиям/столам, безопасное сопряжение
   устройств. Сейчас старый эфир общий для всех клиентов.
4. Автоматическое чтение денег и активных игроков с явным статусом неизвестности.
5. Проверка задержки, батареи и работы при потере связи на реальном телефоне.
6. Оценка диапазонов по действиям. В новой панели скрытые руки пока равновероятны;
   она считает один общий банк и не моделирует побочные банки или ожидаемый выигрыш
   от будущих ставок.
